# Комментарии клиента в Dropbox — что выяснили

Исследование от 25.08.2026. Работа приостановлена, документ фиксирует результат,
чтобы не проверять то же самое заново.

## Вопрос

Клиент оставляет комментарии на картинках в `05_Outbox` через веб-интерфейс Dropbox.
Можно ли получать их автоматически — хотя бы факт «у картинки есть комментарии»,
в идеале тексты — и показывать в трекере?

## Короткий ответ

**Комментарии клиента получить нельзя.** Проверено шесть независимых путей, все
закрыты. Это установленный факт, а не предположение.

**Внутренние комментарии сотрудников — можно.** Доступны через журнал событий
команды: 617 событий за год с текстами, авторами и привязкой к конкретным файлам.

## Что проверено

| Путь | Результат | Чем подтверждено |
|---|---|---|
| Публичный API комментариев | не существует | В спецификации `dropbox-api-spec` нет ни одного маршрута со словом `comment` — ни в `files.stone`, ни в `sharing.stone`, ни в 95 маршрутах `team.stone` |
| Локальная папка на диске | комментариев там нет физически | Живут только на серверах Dropbox, в синхронизированной папке ни файла, ни атрибута |
| `comments2/list_comments`, пользовательский токен | отказ | `400: does not have the required scope 'private:comments.read'` (app 8146803) |
| `comments2/list_comments`, командный токен | отказ | Тот же ответ (app 8216627) |
| `comments2/list_comments`, от имени участника | отказ | Тот же ответ с заголовком `Dropbox-API-Select-User` |
| Журнал событий команды | комментарии клиента не логируются | 0 событий по файлу клиента, `involve_non_team_member` = 0 из 617 |

### Про `private:comments.read`

Это внутренний скоуп Dropbox, им пользуется собственный веб-интерфейс. В App Console
его нет ни в одном блоке — ни в Individual Scopes, ни в Team Scopes, ни в OpenID.
Текст ошибки утверждает, что «владелец может включить его во вкладке Permissions»,
но это неправда: пункта там нет. Проверено на двух разных приложениях.

### Почему свои комментарии видны, а клиента нет

Журнал аудита фиксирует **действия участников команды** — это его назначение.
Комментарий сотрудника попадает туда не как комментарий, а как действие сотрудника.

Внешние люди в команду не входят, их поведение внутреннему аудиту не подлежит.
Отсюда `involve_non_team_member: 0` во всех 617 событиях.

Проверено на конкретных людях: `Katya Palat` — 0 упоминаний, `Palat` — 0,
`Park` — 0. Единственное совпадение по `Stella` оказалось упоминанием `@Stella P`
внутри комментария Дмитра Заєця, а не её собственным сообщением.

Проверено на конкретных файлах:

```
S1_KFF-2631SFACB_KFR1-33WH_Angle01.jpg     0 событий
папка Prefinal/Interior                     0 событий
вся папка Kraus_211_..._Prefinal            0 событий
WFDP-06MB_..._Angle08.jpg (Kraus_215)       0 событий
```

## Что доступно прямо сейчас

Журнал событий команды через `team_log/get_events` с категорией `comments`.
Нужны командные скоупы `events.read` и `team_info.read`, авторизует администратор.

Отдаёт за год:

```
537 file_add_comment       16 file_resolve_comment
  8 file_edit_comment       4 file_delete_comment

авторы: Vasiliy Chaban 330 · Дмитро Заєць 110 · Nadiia Boichenko 60
        Yevhenii Kuchynskyi 25 · Vladislav Sanfirov 20 · Aleksey Demchenko 20
```

Каждое событие содержит текст комментария (`details.comment_text`), путь и `file_id`
файла (`assets[].path.contextual`), автора и дату. Пример:

```
2026-07-10  Дмитро Заєць
/Kraus_211_.../04_JPG/Studio/Studio_White_KPF-1610BB_Angle02.jpg
«надто світлий, глянь пдф»
```

**Важно:** справка Dropbox утверждает, что комментарии в журнал активности
не пишутся. Это неверно — проверено на живых данных.

Тот же источник даёт **авторство изменений**: сейчас трекер показывает
«Studio: прийшло EXR ×22», но не может сказать, кто запускал рендер.

## Непроверенный путь

**Почтовые уведомления.** Dropbox шлёт письмо владельцу файла, всем, кто уже
комментировал, и всем, кого упомянули через `@`. Поскольку сотрудники комментируют
те же файлы, письма про ответы клиента должны приходить им на почту.

Неизвестно, содержит ли письмо **текст** комментария и имя файла, или только
ссылку «перейдите и посмотрите». В документации содержимое письма не показано.

Проверяется за минуту: открыть любое такое письмо и посмотреть. Если текст есть —
путь рабочий и полностью автоматический, читается по IMAP без всякого API Dropbox.

## Вывод

Для комментариев **клиента** единственный надёжный способ — свой ревью-портал
(фаза 4 в `PROJECT.md`). Теперь понятно, что он решает реальную проблему:
сейчас студия видит свои сообщения клиенту в комментариях Dropbox, но не его
ответы. Половина диалога недоступна даже вручную, если не открывать каждую
картинку по отдельности.

## Инструменты

Оба скрипта в репозитории, готовы к повторному запуску:

```bash
npm run probe:comments   # журнал событий команды, нужен командный токен
npm run probe:file       # comments2/list_comments по файлу или папке
```

## Что сделать перед возвратом к теме

- Перевыпустить командный токен — прежний засветился в переписке
- Проверить почтовые уведомления
- Решить по ревью-порталу
